### Первые решения из регрессионных предсказаний

Это **baseline из регрессии и правил**, а не обученная question-conditioned модель.
Вопросы, пороги и margin-фильтры заданы до расчёта метрик.

1. **Какая из двух случайных последовательностей активнее в данном assay?**
   Для каждого assay построены непересекающиеся случайные пары только внутри validation.
   Accuracy всех пар: K562 81,82%, HepG2 82,60%, SK-N-SH 83,12%.
   При истинном разрыве >=0,5 log2FC: 91,65% / 92,11% / 91,27%;
   остаются 64,17% / 64,77% / 69,18% пар соответственно.
   Это не matched-variant benchmark и не проверка эффекта одной мутации.
2. **В какой из трёх клеточных линий одна ДНК наиболее активна?**
   58811 примеров со всеми тремя валидными метками; accuracy **62,57%**.
   Постоянный выбор K562 (по максимальному train mean) — **37,58%**,
   равномерный случайный выбор — ожидаемые 33,33%.
   При измеренном разрыве между первым и вторым assays >=0,5 log2FC:
   accuracy **79,37%**, но только на **26,34%** доступных примеров.
3. **Превышает ли активность порог 0,5 log2FC?**
   Accuracy 84,89–85,57%; balanced accuracy 84,02–84,27%;
   AUROC raw regression score 0,9205–0,9237.
   Эти raw scores не являются вероятностями события, а AUROC не доказывает калибровку.

Проверены также пороги 0 и 1 log2FC; полные числа и доли классов сохранены в отчёте.
Margin-фильтр использует истинную метку при анализе: это не доступный модели
способ abstain. Нельзя выдавать его coverage за deployable risk/coverage curve.
Checkpoint выбирался по этой validation: результаты разведочные, не independent test.
Метки MPRA содержат измерительный шум; качество на близких ответах ограничено и им.

Воспроизведение оценки:

```bash
PYTHONPATH=src .venv/bin/python scripts/evaluate_reg_decisions.py \
  --checkpoint artifacts/reg_5m_mask_v2_seed11/checkpoint_best.pt \
  --data data/processed/malinois/data.parquet \
  --out artifacts/reg_5m_mask_v2_seed11_evaluation
```

GPU используется только для inference. Сохраняется validation_predictions.parquet
с IDs, метками, масками и предсказаниями; исходные последовательности в нём отсутствуют.

### Остальные треки

- ADMET: есть 22 сохранённые GINE-модели и baseline. По соответствующей основной
  метрике из 17 сравнимых endpoints XGBoost выигрывает на 14, GINE — на 3;
  ещё на 5 у старых GINE-отчётов нет PR-AUC. В новом коде выбор метрики исправлен,
  но старые веса от этого автоматически не стали лучше.
- CDS: F1 около 0,99 получен на синтетических интервалах; реальная геномная
  применимость ещё не установлена.
- Rank: текущий trainer не учитывает objective во входе и делит уже построенные
  пары; такой результат нельзя использовать как доказательство decision-качества.
- Bind/Precision и teacher-обёртки остаются исследованиями/заготовками до реальных
  данных, строгих baselines и проверенного выигрыша.

## Выбор направления

Первый законченный продукт: **Minimol-Reg Decide** — специализированные
биологические decision-модели порядка 5–10M параметров с быстрым CPU inference.
Начать с Reg, где уже есть реальные измерения, большой train и сильный baseline.
Второй домен — ADMET, после отдельного сравнения молекулярных моделей.

Jev-подобность означает state + typed question -> typed distribution за прямой
проход, с измеренными калибровкой, качеством и стоимостью. Это не утверждение
о воспроизведении закрытой архитектуры или RLCD TypeSafe. Первый релиз поддерживает
явный конечный набор схем вопросов; произвольный естественный язык не обещается.

## M1. Создать измеримый decision benchmark

Ограниченный контракт первого пилота:

- `choice`: упорядочить A/B по активности в выбранном assay; выбрать из списка
  assays наиболее активный для одной ДНК; расширение на K кандидатов — отдельный тест.
- `noul`: P(y_assay > threshold), с численным threshold и явными единицами.
- `score`: распределение по зафиксированным bins активности, а не субъективная оценка.
- `abstain`: отдельное решение о применимости на основании проверенных сигналов.

Требования к данным:

- [ ] Генерировать decision-задачи из измеренных MPRA меток только исходного train.
  До генерации пар/списков зафиксировать chromosome/locus groups и разделы.
  Не использовать validation/test объекты для train-вопросов.
- [ ] Выделить calibration внутри development-пула с отдельной групповой политикой;
  не калибровать на final test. Сохранять ID вариантов и происхождение каждого вопроса.
- [ ] Включать balanced easy/hard pairs, близкие варианты, thresholds вне сетки train,
  смену assay и direction, перестановку кандидатов, а также неподдерживаемые запросы.
- [ ] Не трактовать noisy near-ties как достоверные бинарные ответы: отдельно
  оценивать неоднозначность по качеству измерений, хранить исходные y и SE.
- [ ] Сравнивать с raw regression + rules, calibrated regression baseline,
  постоянными/случайными ответами и question-only/sequence-only контролями.

Ключевое ограничение: тысячи вопросов об одной молекуле/ДНК не заменяют тысячи
независимых биологических объектов. Статистику считать по группам объектов.

## M2. Обучить маленькую модель решений

- [ ] Переиспользовать Reg encoder. Вектор вопроса содержит type, assay,
  direction, численные threshold/bins и параметры условий.
- [ ] Начать с frozen encoder + обучаемых голов; затем сравнить обучение последних
  блоков и всей модели. Считать общее число runtime-параметров.
- [ ] Для choice использовать общую функцию оценки кандидата с контекстом вопроса
  и маской набора вариантов. Архитектура должна сохранять перестановку ответов
  при перестановке вариантов; индекс позиции не является смыслом кандидата.
- [ ] Для noul обучать BCE/proper scoring loss на наблюдаемых событиях.
  Для score — ordinal likelihood с явно заданными bins.
- [ ] Сохранить regression как auxiliary loss и проверить, помогает ли это.
- [ ] Один encoder pass на объект; несколько лёгких question heads поверх
  закэшированных признаков. Измерять стоимость без кэша и с кэшем отдельно.
- [ ] Проверить монотонность P(y>t) по threshold, согласованность A/B и B/A,
  устойчивость к порядку вариантов и изменение ответа при смене вопроса.
- [ ] Выполнить calibration на отложенных данных; сравнить Brier/NLL, ECE,
  reliability, risk/coverage, class prevalence и качество на OOD.

Порог приёмки: измеримый выигрыш хотя бы в одном заранее выбранном измерении
(качество решений, калибровка, selective risk или стоимость inference) относительно
**калиброванного regression-derived baseline**, без существенных регрессий в остальных.
Три seeds, парные интервалы по группам; final test открывать после фиксации рецепта.
Сама по себе обёртка choice/noul/score или красивый JSON не является этим результатом.

## Реализованный decision-пилот — обновление после экспериментов

M0: атомарные checkpoint, история/статус после эпохи, сохранение optimizer,
Python/NumPy/Torch RNG и генераторов DataLoader, resume на границе эпох.
CPU-тест непрерывного и прерванного обучения проверяет точное совпадение весов.
Исторический parent checkpoint без полного состояния не объявляется resumable.

M1: подготовлен локальный frozen-feature cache с проверкой хэшей. Train — 40001
объект / 18863 группы; development — 4001 / 1774; calibration — 4001 / 1833;
report — 12000 / 5427. Группы определяются точным chr:position, это не
кластеризация гомологов и не гарантия отсутствия перекрывающихся интервалов.
Parent encoder ранее выбирался по общей validation: report является
**exploratory development**, а не независимым финальным тестом. Test не читался.

M2: обучена голова 58498 параметров на frozen encoder; суммарно 5002820.
Общая условная logistic CDF даёт монотонные вероятности порогов и согласованные
ordinal-интервалы; парный выбор антисимметричен. Temperature fit только на
calibration; выбор эпохи — development. Report использует новые числовые пороги
0.25/0.75/1.25/1.75. Primary — object-macro Brier, CI bootstrap по группам.

Реально завершены seed 11, 23, 47 одной головы над одним parent encoder:

- seed11: delta Brier −0.000673; 95% CI [−0.001156, −0.000180], GO.
- seed23: delta −0.000549; CI [−0.001023, −0.000115], GO.
- seed47: delta +0.000409; CI [+0.000038, +0.000753], NO-GO.
- Средний Brier головы 0.082197 ± 0.000592 (sample SD), baseline 0.082468.
- Итог **INCONCLUSIVE**. Это не три независимых обучения encoder и не ансамбль.
- Question-only train-prior Brier 0.185005; игнорирование числового порога 0.144912
  (эти два контроля используют pooled event Brier, не primary object-macro).

Gate требует CI upper < 0 и потери assay-choice accuracy не более 1 п.п.
Сводка учитывает все объявленные seeds, выбор лучшего seed не разрешает сменить
backend по умолчанию. Полные результаты: `artifacts/reg_decide_summary.json`,
`artifacts/reg_decide_seed{11,23,47}/metrics.json`.

M3: self-contained bundle, SDK `RegDecider`, строгие Pydantic-схемы,
`POST /v1/regulatory/decide`, локальная страница `/reg-decide`, CLI и Make targets.
По умолчанию calibrated regression, learned head — явный opt-in. Для длины вне
73..200 bp, неизвестного assay, высокого N-content и train-derived embedding
outlier предусмотрен отказ. Outlier heuristic не является валидированным OOD
детектором. Выбор более двух кандидатов не валидирован и возвращает abstention.

## План достижения преимущества: размеры и серия экспериментов (31 октября 2026)

### Цель и критерий успеха

Начинаем с Reg как наиболее подготовленного направления. Выигрыш Reg не переносится
автоматически на ADMET/CDS. Разделяем два результата: (а) лучшее абсолютное качество
на фиксированном benchmark; (б) лучшее соотношение качества, размера и latency.
Компактная модель может достичь второго без первого. Заранее гарантировать оба нельзя.

Primary — object-macro Brier для заранее заданных невиденных при обучении порогов.
Предлагаемый практически значимый порог: не менее 2% относительного улучшения
против сильнейшего baseline по development; фиксируется до новой серии, не является
полученным результатом. Для подтверждения — paired group-bootstrap CI delta целиком
ниже нуля на закрытом test. Assay-choice accuracy не должна падать более чем на 1 п.п.;
дополнительно фиксируем MAE/Spearman, log loss, risk при coverage 50/75/100%,
качество каждого assay, CPU batch1 p50/p95, размер весов и inference-memory.
CI по объектам не заменяет проверку устойчивости по независимо обученным seeds.
Для финалистов 3 seeds, расширение до 5 если вывод неустойчив; показывать все seeds.

### Лестница размера

Числа ниже реально посчитаны для текущего MinimolReg + RegDecisionHead(hidden=128),
а не взяты из имён preset. Это стартовые конфигурации, не победители benchmark.

- Micro: channels=80, blocks=6 — encoder 236722, голова 27778, всего **264500**.
  Дешёвый контроль и будущий distilled student; не основной кандидат на абсолютное качество.
- Tiny (существующий preset 1m): channels=128, blocks=6 — 599938 + 33922 = **633860**.
  Основная площадка для проверки обучения и абляций. Название 1m означает бюджет.
- Small: channels=208, blocks=8 — 2095602 + 44162 = **2139764**.
  Предпочтительный следующий продуктовый кандидат, если Tiny ограничен capacity.
- Base (5m): 4944322 + 58498 = **5002820**. Сильный внутренний baseline/teacher.
- Large (10m): 9674562 + 74882 = **9749444**. Только после измеренного выигрыша
  от масштабирования; 30M сейчас исключаем из основной серии.

Архитектура с positional pooling или иной головкой изменит эти числа: каждый запуск
обязан записывать фактические параметры. Обучаемые параметры и полный inference-size
указываются отдельно: замороженный encoder всё равно входит в размер модели.

### Этап A — сначала корректный сильный benchmark

1. Зафиксировать manifest/hash данных, интервалы, ориентацию и точное определение
   log2FC/масок. Проверить близкие последовательности и пересечения интервалов.
   Оригинальный test остаётся закрытым; старый report считается уже просмотренным.
2. Из исходного train сформировать group/interval-aware inner train/development/
   calibration; все новые encoder обучать без inner development и calibration.
   Записать баланс assay и активности, не менять split между архитектурами.
   Финалистов оценивать по одному заранее фиксированному протоколу на test;
   provenance внешних checkpoint проверять на пересечение с этим test.
3. Соперники: константа/частоты, k-mer ridge, k-mer boosted trees, текущая 5M +
   честная калибровка, task-trained компактная CNN типа LegNet и Malinois/Basset-style.
   Последние два — реальные локальные сравнения после проверки лицензий и входов,
   а не сравнение наших чисел с несовместимыми таблицами из статей.
4. Для каждой регрессионной модели обучать на одинаковой calibration выборке
   одинаково допустимые probability-mappings. Включить сильный baseline:
   feature-dependent uncertainty без residual correction к mean. Это отделит пользу
   моделирования неопределённости от собственно исправления encoder/ранжирования.
5. Отдельно сообщать track с одинаковыми training-data и track с внешним pretraining.
   Для tuning фиксировать одинаковый GPU-time budget, а также число увиденных примеров;
   ансамбли сравнивать отдельно от single-model, включая суммарную цену inference.

### Этап B — найти рабочий рецепт на Tiny, не наращивать размер вслепую

Первый screen: 6 конфигураций по одному seed, одинаковые inner splits и train budget.
Использовать весь доступный inner train, не только старый cache на 40k.

1. Контроль: current CNN, Huber regression, calibrated probabilities.
2. Та же CNN, end-to-end distribution loss + вспомогательная Huber regression.
3. Как 2, но staged fine-tuning: regression warm-start, затем совместное обучение.
4. Как 2, но позиционно чувствительный readout (несколько spatial bins вместо
   одного глобального вектора); проверить локальные/позиционные взаимодействия.
5. Как 2, но ordinal/discretized activity distribution вместо единственной logistic
   location-scale: проверить, не ограничивает ли форма распределения качество.
6. Компактный efficient-convolution конкурент типа LegNet с тем же budget.

Question losses балансировать по объектам/assay/типам задач. Не считать несколько
порогов одной ДНК независимыми наблюдениями. Pair sampling только внутри train;
сравнить random pairs с трудными близкими по активности парами, сохраняя unbiased
report. Истинные noisy near-ties не превращать в уверенные binary labels.

После screen: максимум 2 рецепта × 3 seeds. Выбор по development primary и guardrails,
не по старому report. LR-range test, warmup/schedule, dropout/weight decay и EMA
проверять ограниченными абляциями после выбора рецепта. Не менять все факторы сразу.
SE использовать только после проверки его смысла/качества: capped noise weighting
и soft labels — гипотезы, а не автоматическая inverse-variance панацея.

Контекст и reverse complement — отдельные биологические абляции. Оригинальный
Malinois использует 600-bp вход с reporter-vector context и учитывает ориентацию.
Нельзя считать reverse complement той же вставки с неизменной меткой по умолчанию.
Сначала восстановить разрешённые construct metadata и проверить постановку.

### Этап C — масштабирование только победившего рецепта

Tiny → 2.14M → 5.00M; сначала по одному seed с сопоставимым data exposure и
конвергенцией, затем 3 seeds у двух финалистов. Раннее прекращение слабых кандидатов
только по заранее заданным development-критериям; короткий недоученный run не доказывает
capacity ceiling. Если train и development плохи — проверить оптимизацию/ёмкость;
если train хорош, development плох — сначала обобщение, данные и регуляризация.
10M добавлять, только если 5M даёт воспроизводимый практически значимый выигрыш над
2M и ещё не достигнут приемлемый latency/quality compromise.

Новый эксперимент не продолжает исторические legacy checkpoints как exact resume.
Нужны новые полные состояния optimizer/RNG и snapshot кода/конфигурации/данных.
Длительность сначала измерить по короткому throughput-профилю; часы без замера не обещать.

### Этап D — teacher/student после получения сильного teacher

Teacher: лучшая 5–10M модель либо явно обозначенный ансамбль. Student: Tiny и Micro.
Совмещать реальные supervised labels с teacher distributions/rankings только на train.
Не дистиллировать из teacher, обученного на student development/calibration/test;
для train-predictions предпочтительны out-of-fold teachers. Distillation не гарантирует
превосходство над teacher: задача — удержать качество при меньшей цене inference.
Выбираем минимальную модель в заранее заданном допуске от лучшего качества
(предлагаемый допуск 1% relative Brier, с CI/guardrails), а абсолютного победителя
отчётливо показываем отдельно. После этого — quantization и CPU/HTTP benchmark.

### Ближайшее конкретное действие

Следующая реализация: immutable inner split manifest + один training harness для
end-to-end probabilistic Tiny и сильного regression control, затем screen этапа B.
Старую frozen-head серию сохраняем как исходный отрицательный/смешанный результат.
Это план новой серии: она ещё не запущена, 2M/10M не объявляются обученными.

Источники архитектурных гипотез:
- LegNet: https://pmc.ncbi.nlm.nih.gov/articles/PMC10400376/ — efficient CNN и
  distribution/soft-classification подход; исходная DREAM-постановка отличается
  от нашего human MPRA, перенос требует локальной проверки.
- Malinois: https://pmc.ncbi.nlm.nih.gov/articles/PMC11525185/ — task-specific
  branched outputs, reporter context, ориентация и процедура fitting.
