### P0. Надёжность оценки и одиночного инференса — до новых больших запусков

- [x] **Исправить зависимость Reg от padding.** Новые модели используют
  `padding_policy=mask_aware`: свёртка и GroupNorm считают только реальные
  позиции, поэтому одиночный и батчевый fp32-вызов совпадают в пределах 1e-4.
  Старые чекпоинты без поля загружаются как `legacy_n_pad`, их предсказания
  на нативной длине не пересчитываются. RC-аугментация переворачивает pad-маску
  вместе с последовательностью. Повторная оценка уже сохранённого Reg-v2 на
  коротких/длинных последовательностях ещё не сделана: тот прогон обучен со
  старой политикой.
- [x] **Выбирать ADMET-чекпоинт по метрике endpoint.** Если рядом с таблицей
  есть manifest с `tdc_metric`, чекпоинт выбирается по -MAE, Spearman, AUROC
  или `average_precision_score`. В отчёт пишутся AUROC, AUPRC, Brier, ECE,
  число наблюдений и доля положительного класса. Уже сохранённые GINE-веса
  выбирались по старому правилу; лучший PR-AUC epoch из них не восстановить.
- [x] **Аудит ADMET после стандартизации.** `cross_split_identity` отдельно
  считает общие InChIKey и общие scaffold. Совпадение scaffold не считается
  дублем метки. Импорт больше не помечает таблицу как неизменённый official test,
  если канонизация отправила строки в quarantine. Политика: изомерный канонический
  SMILES RDKit, стереохимия сохраняется, таутомеры не канонизируются.
  Отдельный строгий internal holdout ещё не построен.
- [x] **Сделать leakage-аудит масштабируемым.** Ветка exhaustive или MinHash
  выбирается до построения пар и работает по уникальным последовательностям.
  Приближённый отчёт явно говорит, что это не исчерпывающая проверка.
  На известной однобуквенной паре MinHash эту пару находит.
- [x] **Исправить границы экспериментального протокола.** В метаданные Reg
  пишутся отдельные `training_seed` и `split_seed`, источник split и
  group-bootstrap CI макро-MAE. В отчёте прямо сказано, что это интервал
  того же validation, на котором выбирался чекпоинт, а не независимый test.

## Подтверждённые результаты разбора

- В прежней голове Reg выход имел вид `linear(encoder(sequence) + assay_embedding)`.
  Различия между assays сводились к постоянным сдвигам в нормированной шкале.

  Теперь оно выполняет обновление с нормировкой на фактическое число батчей окна.
  Прежние запуски с `accumulation_steps=1` эта ошибка не затрагивала.
- Выбор регрессионного чекпоинта по validation MAE уже реализован.
  Высокий Spearman сам по себе не гарантирует правильный масштаб предсказаний.

- [ ] Не подбирать mixed-task чекпоинт только по регрессионным задачам:
  явно задать критерий выбора для всех обучаемых типов задач.
- [ ] Перспективные варианты повторить на seeds 11, 23, 47; приложить OOD по
  сходству с train и проверку пересечения молекул/scaffolds.

Приёмка: у каждого endpoint есть сравнимый baseline, число наблюдений,
критерий выбора чекпоинта и вариативность по seeds. Слабые задачи получают
конкретную причину/следующую абляцию, а не общий вывод «архитектура плохая».

## Этап 4. Следующее развитие

- [ ] CDS: сохранить синтетический F1 около 0,99 как проверку пайплайна;
  отдельно проверить качество на утверждённых реальных аннотациях,
  species/assembly holdout, boundary F1 и reverse-complement согласованность.
- [ ] После сравнения Reg-5M исследовать 10M; 30M запускать при обоснованном
  ограничении меньшей модели и измерять качество вместе с задержкой/памятью.
- [ ] Bind и Precision развивать после проверки данных и сравнения с ligand-only,
  protein-only, zero-delta и mutation-aware baseline.
- [ ] Дистилляцию принимать только при улучшении отложенной метрики относительно
  supervised-модели с сопоставимым бюджетом.

Для каждого нового эксперимента сохранять конфиг, seed, хэш данных, split,
тип головы/преобразование меток, число шагов, лучший epoch и метрики baseline.
Итоговый test открывать только после фиксации рецепта на validation.
