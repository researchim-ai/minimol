# Задание: исправление и улучшение обучения Minimol

Дата актуализации: 29 октября 2026.

Этот документ дополняет оба основных ТЗ и задаёт ближайший порядок работ.
Его приоритет — проверить исправленный Reg-5M и качество ADMET до увеличения моделей.

## Подтверждённые результаты разбора

- В прежней голове Reg выход имел вид `linear(encoder(sequence) + assay_embedding)`.
  Различия между assays сводились к постоянным сдвигам в нормированной шкале.
  Независимые реакции клеточных линий на последовательность такая голова не представляла.
- Добавлена нелинейная активация перед общим выходным слоем. В контрольном
  обучении на 16 последовательностях с противоположными целями двух assays
  после 300 обновлений старая голова получила MSE 0,377778, исправленная —
  практически ноль. Это проверка выразительности; прирост на Malinois ещё не измерен.
- Старые чекпоинты через `MinimolReg.from_metadata` используют `legacy_linear`.
  Их предсказания нельзя молча пересчитывать с новой активацией.
- Цикл обучения терял последнее неполное окно накопления градиентов.
  Теперь оно выполняет обновление с нормировкой на фактическое число батчей окна.
  Прежние запуски с `accumulation_steps=1` эта ошибка не затрагивала.
- Выбор регрессионного чекпоинта по validation MAE уже реализован.
  Высокий Spearman сам по себе не гарантирует правильный масштаб предсказаний.
- Сохранённый Malinois Reg-5M: 156810 обновлений, 30 эпох,
  validation macro Spearman 0,7736 и macro MAE 0,4715. Это исходная точка
  для сравнения старой и новой головы, а не результат исправленной архитектуры.
- В текущей проверке 75 тестов прошли без `tests/unit/test_api.py` и slow-тестов.
  API-тесты зависли и были остановлены; они не считаются прошедшими.
- NVIDIA-драйвер в сессии диагностики недоступен. Повторное полное обучение
  после исправления головы ещё не запускалось.

## Этап 2. Повторное обучение Reg-5M

Использовать `configs/reg_5m_malinois_v2.yaml`, отдельный каталог результата
`artifacts/reg_5m_malinois_v2`. Существующие чекпоинты не перезаписывать.

```bash
PYTHONPATH=src .venv/bin/python -m minimol.training.train_reg \
  --config configs/reg_5m_malinois_v2.yaml \
  --out artifacts/reg_5m_malinois_v2
```

- [ ] До большого запуска выполнить проверку переобучения маленького фиксированного train-набора.
- [ ] Для лучшего чекпоинта измерить train и validation MAE, RMSE, Pearson и
  Spearman отдельно для K562, HepG2 и SK-N-SH; сохранить кривые по эпохам.
- [ ] Проверить среднее и разброс предсказаний относительно меток, сдвиг масштаба,

## Этап 3. Диагностика ADMET по каждому endpoint

Предварительное сравнение сохранённых моделей с медианой train на validation:
растворимость — снижение MAE примерно 52%, липофильность — 34%; half-life
хуже примерно на 2%, VDss и PPBR лучше лишь на 2–3%. Это сравнение с константой,
а не доказательство преимущества над сильным молекулярным baseline.

- [ ] Для каждого endpoint сопоставить GINE с train mean/median, дескрипторным
  XGBoost или явно названным fallback и fingerprint kNN на идентичных splits.
- [ ] Для регрессии сохранить MAE/RMSE/корреляции; для классификации — AUROC,
  AUPRC, Brier и калибровку, а также размер выборки и долю положительного класса.
- [ ] Для half-life, VDss, PPBR и clearance проверить единицы, выбросы,
  распределения train/validation, цензурированные отношения и качество меток.
- [ ] Логарифмическое преобразование исследовать отдельной абляцией только
  при соответствии смыслу и области значений endpoint. Правило преобразования
  сохранять в чекпоинте, а метрики считать также в исходных единицах.
- [ ] Сравнить маленький MPNN/GINE с 5M при одинаковом протоколе и бюджете.
- [ ] Не подбирать mixed-task чекпоинт только по регрессионным задачам:
  явно задать критерий выбора для всех обучаемых типов задач.
- [ ] Перспективные варианты повторить на seeds 11, 23, 47; приложить OOD по
  сходству с train и проверку пересечения молекул/scaffolds.

Приёмка: у каждого endpoint есть сравнимый baseline, число наблюдений,
критерий выбора чекпоинта и вариативность по seeds. Слабые задачи получают
конкретную причину/следующую абляцию, а не общий вывод «архитектура плохая».

## Этап 4. Следующее развитие

- [ ] CDS: сохранить синтетический F1 около 0,99 как проверку пайплайна;
  отдельно проверить качество на утверждённых реальных аннотациях,
  species/assembly holdout, boundary F1 и reverse-complement согласованность.
- [ ] После сравнения Reg-5M исследовать 10M; 30M запускать при обоснованном
  ограничении меньшей модели и измерять качество вместе с задержкой/памятью.
- [ ] Bind и Precision развивать после проверки данных и сравнения с ligand-only,
  protein-only, zero-delta и mutation-aware baseline.
- [ ] Дистилляцию принимать только при улучшении отложенной метрики относительно
  supervised-модели с сопоставимым бюджетом.

Для каждого нового эксперимента сохранять конфиг, seed, хэш данных, split,
тип головы/преобразование меток, число шагов, лучший epoch и метрики baseline.
Итоговый test открывать только после фиксации рецепта на validation.
